## Project overview

HeadSense is a Flutter app **exported from FlutterFlow** (see the initial commit "Exportacion inicial desde FlutterFlow"). Most of `lib/` is FlutterFlow-generated scaffolding — pages, models, theme, nav, and Firestore schema classes are regenerated by FlutterFlow exports and follow rigid, repetitive conventions rather than hand-rolled architecture. The two places meant for genuine hand-written code are `lib/custom_code/` (custom widgets/actions/functions) and `firebase/custom_cloud_functions/` (custom backend logic) — see Architecture below.

Backend is Firebase (Firestore, Cloud Functions, Auth, Cloud Messaging, Crashlytics, Performance). Firebase project id: `head-sense-1111` (see `firebase/functions/package.json` scripts).

## Commands

Run all Flutter commands from the repo root (`head_sense/`).

```bash
flutter pub get                 # install/sync Dart dependencies
flutter analyze                 # static analysis (uses analysis_options.yaml / flutter_lints)
flutter test                    # run all tests
flutter test test/widget_test.dart   # run a single test file
flutter run -d chrome           # run on web (project uses url_strategy / go_router web routing)
flutter run                     # run on a connected device/emulator
flutter build web               # production web build
flutter build apk / build ios   # mobile builds
```

Firebase Cloud Functions (two separate codebases, deployed independently — see `firebase/firebase.json`):

```bash
cd firebase/functions && npm install
npm run lint                    # eslint, --max-warnings=0
npm run serve                   # local emulator (project head-sense-1111)
npm run shell                   # functions shell against head-sense-1111
npm run logs                    # tail deployed function logs

cd firebase/custom_cloud_functions && npm install   # separate function codebase, its own package.json
```

There is no separate lint config beyond `flutter analyze` / the functions' `eslint`; there is no CI config in this repo to mirror.

## Architecture

### Two Firebase Functions codebases
`firebase.json` declares two independent function sources/codebases deployed together:
- `firebase/functions` — the original FlutterFlow-managed backend logic (payments/Braintree/Stripe/Razorpay, OneSignal, LangChain-based AI wiring, FCM token management, push notification triggers on `ff_push_notifications`).
- `firebase/custom_cloud_functions` — hand-written functions specific to this app's domain (e.g. `update_dashboard_metric.js` computes rolling symptom-severity aggregates over 30/60/90/180/365-day windows, `scheduled_reminders.js`). These have Spanish-language comments; keep that style consistent when editing them rather than translating wholesale.

Corresponding client-side call wrappers live in `lib/backend/cloud_functions/` (built-in) and `lib/backend/custom_cloud_functions/` (custom, via `custom_cloud_function_response_manager.dart`).

### FlutterFlow generated conventions (do not hand-edit patterns, only content)
- **Pages**: each screen lives under `lib/pages/<page_name>/` as a pair — `<name>_widget.dart` (the `StatefulWidget`, `routeName`/`routePath` statics, `initState` "on page load" actions) and `<name>_model.dart` (FlutterFlow's per-page state/controllers container, created via `createModel(context, () => XModel())`). Follow this same widget+model split when adding new pages so future FlutterFlow re-exports don't conflict.
- **Components**: reusable non-page widgets live under `lib/components/`, same widget+model pairing pattern as pages.
- **Routing**: centralized in `lib/flutter_flow/nav/nav.dart` using `go_router`. `AppStateNotifier` (in the same file) drives auth-gated redirects; routes are declared as a list of `FFRoute`s referencing each page's `routeName`/`routePath` statics. The bottom-nav tab shell (`NavBarPage`, tabs: DiaryTodoList, Reminders, DailyDiaryPage, Dashboard) lives in `lib/main.dart`.
- **Firestore schema**: one immutable record class per collection in `lib/backend/schema/*_record.dart` (e.g. `DiaryEntriesRecord`, `RemindersRecord`, `MetricsRecord`, `DashboardRecord`, `StudiesRecord`, `UsersRecord`). Each wraps a `DocumentReference`/`Map` snapshot with typed getters; query/stream helpers are generated alongside in `lib/backend/backend.dart`. Nested/reusable value types are under `lib/backend/schema/structs/`.
- **App-wide state**: `lib/app_state.dart`'s `FFAppState` is a singleton `ChangeNotifier` (FlutterFlow "App State" variables) — mutate fields via its setters and it notifies listeners; some fields are persisted (see `initializePersistedState`).
- **Theme**: `lib/flutter_flow/flutter_flow_theme.dart` centralizes all colors/text styles — use `FlutterFlowTheme.of(context)` rather than hardcoding colors, matching the rest of the codebase.
- **Auth**: `lib/auth/` wraps Firebase Auth behind `BaseAuthUser`/`AuthManager` abstractions, with provider-specific implementations in `lib/auth/firebase_auth/` (email, Google, Apple, GitHub, anonymous, JWT). `currentUserReference` / `currentUser` (from `auth_util.dart`) are the standard way to access the logged-in user elsewhere in the app.

### Custom code (the actual hand-written surface)
- `lib/custom_code/widgets/` — bespoke widgets not expressible in FlutterFlow's builder, notably the charting widgets used on the Dashboard: `clinical_donut_chart.dart`, `stacked_severity_bar.dart`, `symptom_bar_chart.dart`, `severity_legend_list.dart` (built on `fl_chart`). New custom widgets get registered in `lib/custom_code/widgets/index.dart`.
- `lib/flutter_flow/custom_functions.dart` — custom Dart helper functions exposed to FlutterFlow's action/binding system.

### Domain shape
Core Firestore collections: `users`, `diary_entries` (daily symptom diary, keyed by `entryDateKey` = `yyyy-MM-dd`), `diary_todo`, `reminders`, `metrics`, `daily_values`, `dashboard` (precomputed aggregates written by `update_dashboard_metric.js`), `studies`, `plans`, `responses`. The app's main flows are: daily symptom diary entry, reminders, a dashboard of symptom-severity trends/charts, BMI/weather-linked pages, and study enrollment (`join_study`).
